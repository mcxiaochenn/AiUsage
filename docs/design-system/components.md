# 组件规范

本页定义组件职责和复用边界。它不是现有 Widget 名称清单，也不要求一次性构建完整组件库。实现阶段应先收敛高频模式，再按页面迁移。

## 通用规则

- 相同职责必须共享组件或共享明确的主题规则。
- 新组件必须解决可复用的语义，不因单个页面的视觉差异而新增。
- 组件接收业务所需的状态和内容，不在内部重新解释 Provider 原始数据。
- 组件必须定义默认、加载、禁用、选中、错误等与其职责相关的状态。
- 高度默认由内容决定；固定尺寸仅用于图标、头像、进度指示和数据格等明确元素。
- 组件不得假定英文长度、单行文字或固定文本缩放。

## 页面框架

### 主导航 Scaffold

用于概览、账户、历史和设置四个一级页面。compact 布局使用底部导航，expanded 布局使用侧边导航。顶部 Provider 切换、刷新和添加账户属于应用级操作，不应在每个页面重复实现。

### 二级页面 Scaffold

用于账户详情、诊断、设置分类和关于页。必须提供安全区内的标准 AppBar、明确标题和返回行为，并隐藏一级导航。正文不重复同名大标题。

### 标准页面内容容器

后续应统一页面边距、最大阅读宽度和 compact/expanded 行为。页面只描述内容顺序，不自行发明宽屏约束。

## 内容结构

### 页面标题与区块标题

- 一级页面可以在正文显示任务标题；二级页面由 AppBar 提供标题。
- 区块标题只划分信息组，不能模拟新的页面层级。
- 标题与其内容必须在间距和语义树中保持关联。

### 设置分组

相关选项放入同一组，组内使用标准 ListTile、Radio 或 Switch 行为。标题、说明和当前值的呈现方式应统一；不在设置项中混入即时危险操作。

## 信息展示

### 账户头卡

用于概览中确认当前 Provider 和账户。主标题优先自定义名称，副标题显示 Provider 与套餐或安全的账户标识。强调色来自主题，品牌仅由头像或图标表达。

### 账户管理卡

用于账户页的选择和管理。必须区分主名称、原始标识、状态、来源、最后同步和操作区。选中状态不能只靠背景色；危险操作与普通操作必须视觉分离。

### 指标卡

额度、余额、Token 摘要和 Reset Credits 共享“标题—关键值—说明/状态”的信息骨架。不同数据类型可以有专属内容，但标题、指标和辅助信息的 Typography 与间距关系应一致。

网格中的卡片在同一布局能力下应保持视觉节奏；大字体时允许自然增高，不通过截断强制等高。

### 详情项

详情项用于标签与值的稳定映射。compact 布局允许上下排列，expanded 布局可以左右排列。敏感信息必须在进入组件前完成脱敏。

## 状态反馈

后续共享状态组件至少覆盖：

- **加载**：首次加载、局部更新和按钮提交。
- **空状态**：没有账户、没有数据或 Provider 不支持某能力。
- **错误**：阻塞错误、可重试错误和保留缓存的更新错误。
- **缓存/陈旧**：内容仍可读，但必须显示采集时间和状态。
- **部分成功**：部分余额或接口成功，不能伪装成完整成功。
- **凭据问题**：凭据过期、无权限或需要重新认证。
- **危险**：不可逆或高风险操作。

每个状态应包含适当的图标、标题、说明和可选操作。不得只改变颜色或只输出原始错误字符串。

## 操作组件

- **主要操作**：当前区域最重要且安全的下一步，同一区域通常只有一个。
- **次要操作**：补充路径、取消或非关键操作。
- **危险操作**：删除账户、清空数据或永久自毁；必须使用危险语义并清楚描述范围。
- **图标按钮**：适合公认且空间受限的操作，必须有 Tooltip；不清晰时使用文字按钮。
- **操作菜单**：用于低频并列操作，不隐藏用户完成主要任务所必需的入口。

按钮显示加载时必须防止重复提交，同时保持原操作语义可辨认。

## 输入组件

- 登录表单字段顺序遵循用户决策顺序，自定义名称与凭据输入保持明确分组。
- 敏感字段默认隐藏，并说明存储和使用边界。
- 文件导入使用“未导入/已导入”等状态，不显示完整本地路径。
- 校验错误紧邻相关字段；服务端或跨字段错误显示在表单级区域。
- Radio、Switch 和选择控件使用完整可点击行，标签本身不承担未说明的副作用。

## 浮层组件

### Dialog 与 Bottom Sheet

compact 触摸场景优先使用 Bottom Sheet 承载短选择；需要集中输入、阻塞确认或较复杂内容时使用 Dialog。expanded 布局可以使用受宽度约束的 Dialog。

浮层必须支持取消、系统返回、键盘导航和大字体滚动，不能依靠固定内容高度。

### SnackBar

用于短暂、非阻塞且不要求持续阅读的结果。阻塞错误、持续缓存状态或不可逆后果不能只通过 SnackBar 表达。

### Tooltip

为图标和数据单元提供快速说明。Tooltip 不能是触摸用户获取必要信息的唯一方式。

## 数据组件

### 进度条

进度条必须同时有文字值或可访问标签。阈值状态通过主题语义表达，不直接写入临时颜色。

### Token 热力图

保留每日、每周和累计视图、主题派生色阶、图例与准确数值详情。有效零值可交互；今天、未来或真正不可用的格子不伪装成零值。

点击、悬停和读屏必须能够获得同一准确 Token 数。颜色深浅不能成为唯一数据入口。

### 诊断原文

原始内容默认折叠，使用适合技术文本的排版并允许复制或横向处理。诊断组件不得绕过现有脱敏边界。

## 新组件检查

新增组件前必须回答：

1. 是否已有相同职责的组件或 Material 组件？
2. 新差异是业务内容、状态，还是确实需要新的视觉结构？
3. compact、expanded、大字体和中英文如何呈现？
4. 需要哪些鼠标、键盘、触摸和 Semantics 行为？
5. 该模式是否需要同步更新本页或基础规范？
