# 设计原则

本页记录 AiUsage 长期稳定的设计判断。具体组件和视觉值可以演进，但不得无意违背这些原则。

## 1. 一致性优先于新奇

相同职责应使用相同的信息层级、组件和交互。新页面先复用现有模式，不为“更特别”而增加渐变、玻璃效果、额外阴影或无意义动效。

一致性不等于复制临时实现。若现有页面存在多个近似写法，应按语义归并，而不是选择其中一个继续扩散。

## 2. 信息清晰优先于装饰

AiUsage 的核心任务是让用户快速判断账户、额度、余额和同步状态。布局必须优先回答：

- 当前查看哪个 Provider 和账户。
- 数据是什么、何时获取、是否来自缓存。
- 是否需要用户操作。
- 操作会产生什么后果。

装饰元素不能与关键指标争夺注意力，卡片也不能成为无差别包裹所有内容的默认答案。

## 3. 本地优先必须可感知

缓存、同步和凭据状态属于产品体验，而不是仅供诊断的实现细节。界面必须在相关场景清楚区分新鲜数据、缓存数据、部分成功、同步失败和凭据过期。

不得用仍在缓存中的旧数据营造“实时成功”的假象，也不得因后台刷新失败清空仍可阅读的有效缓存。

## 4. Theme 提供语义，不只提供颜色

Material 3 和系统动态取色是主题基础。动态色可以改变实际色值，但不能改变主要操作、错误、警告、选中和表面层级的含义。

业务组件应请求语义角色，不应自行判断明暗主题后选择颜色。任何硬编码品牌色或图表色阶都属于受控例外。

## 5. Provider 品牌服务于识别

ChatGPT、DeepSeek 和 Xiaomi MiMo 的品牌图标用于快速辨认来源。品牌色不得取代应用的操作色、状态色或文本层级，也不得降低动态主题下的对比度。

账户头像、Provider 图标和文字标识应互为回退，不能让网络头像是否加载成功决定信息是否可识别。

## 6. 移动端优先，宽屏主动适配

compact 布局优先完成核心任务和单手操作。expanded 布局应通过内容宽度、网格和侧边导航提高可读性，而不是把手机页面无限拉宽。

响应式变化由内容和交互能力驱动，不以某个设备型号为目标。后续桌面适配不得要求重写移动端信息架构。

## 7. 本地化与无障碍是默认输入

中英文、长名称、大字体、触摸、鼠标、键盘和读屏不是收尾测试，而是组件设计的默认场景。

颜色不能成为状态的唯一表达。图标按钮必须有可访问名称；图表必须提供准确数值；文本应优先自然增高，而不是依赖截断维持固定卡片高度。

## 8. 反馈与操作强度匹配

普通操作使用普通反馈；可重试失败使用明确说明和重试入口；不可逆操作使用危险色、渐进披露和清楚后果。

普通退出、移除账户和永久自毁不是同一风险等级，不得共享相同的确认强度。危险样式也不得用于吸引点击。

## 9. 动效解释变化

动效只用于表示状态变化、空间关系或操作反馈。它必须短、可中断，并在系统要求减少动态效果时安全降级。

不为滚动、卡片出现或普通数字变化增加持续装饰动画。

## 10. 渐进迁移，不做视觉大爆炸

Design System 的落地目标是收敛现有实现。迁移应按基础层、共享组件和页面逐步进行，每一步保持业务行为不变并可单独验证。
