# 交互规范

本页统一导航、反馈和状态变化。具体动画时长和平台细节在后续实现阶段验证后集中定义。

## 导航与返回

- 一级页面使用主导航切换，不为同一目的叠加新的路由层级。
- 二级页面通过标准 AppBar 返回来源页；系统返回和顶部返回必须等价。
- Android 在一级非概览页面返回时先回概览；概览按现有双返回规则退出。
- Dialog、Bottom Sheet 和其他临时浮层必须优先于页面路由关闭。
- 导航不能触发无关的网络刷新；页面按需数据遵循各自缓存与刷新策略。

## 指针、触摸与键盘

- 整卡可点击时使用统一点击区域，并提供可见的按压、悬停和焦点反馈。
- 卡片内部存在独立操作时，必须避免整卡点击和子操作语义冲突。
- 长按不能作为唯一入口。
- 鼠标悬停只提供临时信息或强调，不改变持久状态；鼠标移出后恢复此前状态。
- 键盘焦点顺序应符合视觉和阅读顺序，Enter/Space 行为与点击一致。
- 禁用状态必须保留操作名称和不可用原因所需的上下文。

## 选择状态

- Provider 切换和账户切换必须立即反映当前上下文，并优先展示对应缓存。
- 选择状态至少使用图标、边框、文字或结构中的一种非颜色提示。
- 切换选择不能把上一个账户的名称或数据短暂显示为当前账户内容。
- 演示模式的选择与真实账户选择相互隔离。

## 刷新与提交

### 首次加载

尚无可显示内容时使用页面或区域加载状态。加载占位必须说明正在获取什么，且不能无限占据固定空白而没有失败出口。

### 静默更新

已有缓存时保持内容可读，以轻量进度或更新时间提示后台更新。失败后保留缓存并明确标记“更新失败，显示缓存”。

### 手动刷新

用户触发后立即提供反馈并防止重复请求。刷新只作用于用户当前理解的范围；需要刷新多个来源时应明确状态。

### 表单提交

提交期间禁用重复提交，保留输入内容。字段错误就地显示；网络或服务端错误显示在表单级区域，并提供可恢复路径。

## 状态反馈选择

- **页面状态**：阻塞当前任务的加载、空数据或错误。
- **区域状态**：只影响某张卡片、某组 Provider 数据或某项详情。
- **持久提示**：缓存、凭据过期、后台限制等在问题消失前仍需可见的信息。
- **SnackBar**：清空成功、复制成功等短暂结果。
- **Dialog**：需要明确选择或确认后果的阻塞交互。

原始服务端错误默认作为诊断详情，不直接替代本地化主提示。

## Dialog 与 Bottom Sheet

- 简短选择在 compact 布局可使用 Bottom Sheet，在 expanded 布局可使用 Dialog。
- 输入、认证和危险确认使用可滚动、受宽度约束的 Dialog 或完整二级页面。
- 主操作放在阅读顺序末端，取消路径始终可见。
- 系统返回、点击取消和显式关闭必须得到一致结果。
- 浮层关闭后清理仅属于该流程的临时数据，例如验证码、文件字节和密码。

## 错误、缓存与重试

- 错误提示必须说明用户当前还能做什么。
- 401/凭据过期引导重新添加或认证，不用模糊的“登录失败”覆盖凭据语义。
- 429、网络失败和服务端错误在有缓存时继续展示缓存；重试入口不能造成高频循环。
- 部分成功必须保留合法数据，并标记缺失范围。
- 无历史能力与历史加载失败是不同状态，文案和操作不得混用。

## 危险操作

- 删除账户应说明会删除的本地账户与缓存范围，并要求确认。
- 清空诊断只影响诊断日志，不能使用会暗示清空账户的文案。
- 永久自毁保持现有渐进解锁、双重冷却、失败不落锁和不可恢复说明。
- 任一危险流程取消或离开页面时，临时解锁状态必须重置。
- 危险色只用于后果真实危险的操作，不用于普通警告或吸引注意。

## 数据交互

- 图表悬停提供临时详情，点击提供持久详情；两者使用同一格式化逻辑。
- 触摸用户无需依赖 Hover 或 Tooltip。
- 点击空白或显式关闭可以清除选择，切换视图清除不再有效的选择。
- 横向滚动与单元点击不能相互阻断；读屏用户可按逻辑顺序访问有效数据。

## 动效方向

- 页面和状态变化优先使用 Material 默认动效。
- 自定义动效必须说明它所表达的状态或空间关系。
- 动效应可中断，不能阻塞操作，也不能延迟危险信息出现。
- 遵循系统减少动态效果设置；降级后仍需有清楚的静态反馈。
