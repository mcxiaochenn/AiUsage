# 响应式与可访问性

AiUsage 当前以 Android 为主要验证平台、iOS 为主要适配平台，并为后续桌面支持保留 expanded 能力。本页定义布局和输入能力，不绑定具体设备型号。

## 布局能力

后续代码应使用集中定义的语义布局能力：

- **compact**：单列内容、底部主导航、触摸优先，关键操作必须在窄屏和大字体下可达。
- **medium**：允许有限网格或更宽浮层，但仍保持移动端信息顺序。
- **expanded**：侧边主导航、受约束的阅读宽度和多列信息布局，同时完整支持鼠标与键盘。

具体阈值在实现阶段统一确定。业务页面不得继续新增独立的匿名断点；确需例外时记录内容原因，而不是设备名称。

## 页面与网格

- 页面内容应使用共享容器控制边距和最大阅读宽度。
- compact 默认单列；只有单元在大字体下仍能完整表达时才使用多列。
- expanded 网格根据内容最小可读宽度决定列数，不用固定设备宽度推断。
- 卡片允许随内容自然增高；视觉对齐不能以隐藏文本或制造溢出为代价。
- 二级页面保持标准 AppBar 和安全区，不显示一级底部导航。

## 长内容

- 自定义名称和核心账户标识优先完整显示，可自然换行。
- AppBar、Provider 下拉和重复辅助标识可以单行省略，但必须保留其他查看完整信息的入口。
- URL、API Key 指纹、诊断文本和原始响应使用符合内容特性的换行或滚动方式。
- 操作按钮在窄屏下使用 Wrap、纵向排列或菜单，不能压缩成不可辨认的文字。
- 不使用固定尾部宽度承载可能变长的本地化文本。

## 文字缩放与本地化

- 设计和测试至少覆盖英文、简体中文以及 1.5×、2× 文字缩放。
- 文本放大时保持阅读顺序，卡片和浮层应滚动或增高。
- 不依赖英文短词决定按钮、SegmentedButton 或导航宽度。
- 数字、日期、金额和复数文案通过本地化层输出；布局不拼接不可重排的长句。
- 服务端原始标签可以保留，但其 UI 解释必须本地化。

## 触摸、鼠标与键盘

- 交互目标遵循 Material 和平台的最小可触达要求。
- IconButton、热力图小格等视觉尺寸较小的元素必须保留足够命中区域。
- Hover 只增强信息；所有操作必须有触摸路径。
- 所有主要流程必须能通过键盘完成，焦点样式清晰且不只依赖颜色。
- 横向滚动区域应允许触摸拖动、滚轮/触控板操作，并避免吞掉单元点击。

## Semantics 与辅助技术

- 图标按钮必须有本地化名称。
- 头像和品牌图标若旁边已有等价文字，可作为装饰；否则提供身份标签。
- 选中、禁用、展开和按钮状态必须暴露给 Semantics。
- 错误提示应与相关控件建立可理解的阅读顺序。
- 热力图的有效格必须读出日期和准确 Token 数；不可用占位不进入可操作语义树。
- 原始诊断内容默认折叠，展开操作及状态必须可读。

## 颜色与对比度

- 亮色、暗色、动态取色均需验证文字、图标、边界和状态对比度。
- 选中、成功、警告、错误和用量等级不能只靠色相区分。
- Provider 品牌图标在任意主题表面上都要保持边界和可辨认性。
- 禁用状态仍需可读，不能通过过低透明度让标签消失。

## 验证矩阵

涉及布局或共享组件的 UI 变更至少检查：

| 维度 | 最小覆盖 |
| --- | --- |
| 语言 | English、简体中文 |
| Theme | 亮色、暗色、动态取色回退；涉及主题时补动态色输入 |
| 宽度 | 360dp compact、一个平板/桌面 expanded 场景 |
| 字体 | 默认、1.5×、2× |
| 输入 | 触摸；有桌面交互时补鼠标和键盘 |
| 状态 | 正常及该组件适用的加载、空、错误、缓存、禁用状态 |

稳定的共享组件应逐步增加 Widget 契约测试；对主题和布局高度敏感的组件再增加少量 Golden 测试。Golden 不替代语义、键盘和行为测试。
