# Design System 迁移计划

迁移目标是在不改变业务逻辑、Provider 数据含义和安全边界的前提下，让规范逐步成为代码层的真实来源。禁止一次性重写全部页面。

## 实施原则

- 每个阶段都应形成可独立验证、可独立回退的提交。
- 先建立基础和复用边界，再迁移页面。
- 提取组件时保持现有行为和大致外观，不夹带产品功能调整。
- 只抽取已出现重复职责或即将被多个页面使用的模式。
- 当前页面中的临时写法不能因为“兼容旧样式”继续复制到新代码。

## 阶段 0：文档与基线

**目标**：建立本目录、根 `AGENTS.md` 入口和现状审计。

**交付**：

- Design System 文档可被后续 Agent 独立发现和理解。
- 当前模式、问题和合理例外有明确记录。
- 不修改任何 Flutter UI。

## 阶段 1：Theme 与基础层

**状态：基础实现已完成。** `AiUsageTheme`、语义 Typography/Spacing/Shape/Layout/尺寸 Token、Warning ThemeExtension 和上下文扩展已落地；后续只按真实需求补充角色。

**目标**：建立单一 Theme 构建入口、最小语义 token 和集中响应式能力。

**方向**：

- 统一亮色、暗色、动态取色回退和组件 Theme。
- 增加成功、警告、信息、缓存和部分成功等必要语义。
- 从当前高频值收敛 Typography、Spacing、Shape 和内容宽度角色。
- 建立 compact、medium、expanded 查询方式和标准页面内容容器。

**约束**：不得在这一阶段主动重做页面视觉；只迁移足以验证基础层的少量代表组件。

## 阶段 2：共享组件

**状态：最小公共组件已建立。** 页面列表、二级 Scaffold、区块标题、空/状态反馈和响应式网格已有实现；业务专属卡片仍保留在 Feature 层，避免过度抽象。

**目标**：优先收敛重复且高频的结构。

建议顺序：

1. 主/二级页面 Scaffold 与标准内容容器。
2. 页面标题、区块标题和设置分组。
3. 加载、空、错误、缓存、部分成功和凭据状态。
4. 指标卡骨架、详情项和账户/Provider 展示。
5. Dialog、Bottom Sheet、表单错误和操作反馈。

每个共享组件都应定义所需状态、响应式行为和 Semantics，再迁移调用方。

## 阶段 3：低风险页面

**状态：当前生产 UI 已完成 Token 级迁移；后续页面拆分必须继续复用相同入口。**

按以下顺序迁移：

1. 设置首页和设置分类页。
2. 关于页。
3. 诊断页。
4. 登录与导入 Dialog/Bottom Sheet。

这些页面数据依赖较少，适合验证页面容器、设置分组、表单、浮层和危险操作规范。

## 阶段 4：核心页面

**状态：概览、账户、历史图表和认证浮层已完成 Token 级迁移；业务行为与图表算法未改变。**

按以下顺序迁移：

1. 账户页与账户详情。
2. 概览账户头卡及额度/余额卡片。
3. 历史摘要与 Token 图表。

核心页面迁移必须保持缓存首帧、Provider 分流、演示模式和原有交互算法。视觉统一不能改变数据何时请求、如何聚合或如何脱敏。

## 阶段 5：收敛与门禁

**状态：源码审计门禁已建立。Typography 与颜色保持严格限制，低风险几何值支持带理由的行级例外；视觉契约/Golden 仍按高价值组件逐步补齐。**

**目标**：删除迁移产生的重复样式并建立长期防漂移能力。

- 清理本轮迁移产生的孤立组件和局部视觉常量。
- 更新 `current-audit.md`，移除已解决问题并登记剩余例外。
- 为稳定 Theme、响应式容器和共享组件补充契约测试。
- 为少量主题敏感、高复用组件建立 Golden 基线。
- 在 UI Review 中固定使用本页 Definition of Done。
- 维护轻量静态检查：严格阻止 Typography 与颜色漂移；Spacing、尺寸、Shape 和特殊布局只接受紧邻代码且带理由的受控例外。

## 页面迁移 Definition of Done

每个页面只有同时满足以下条件才算完成：

- 优先使用已定义的 Theme、语义 token 和共享组件；合理局部例外已在代码旁说明，重复值已收敛。
- 保持原业务行为、Provider 语义、安全存储和缓存边界。
- English、简体中文下信息层级和操作完整。
- 亮色、暗色和动态取色回退下语义一致、内容可读。
- 360dp compact、一个 expanded 场景以及 1.5×/2× 字体下无溢出。
- 适用的加载、空、错误、缓存、部分成功、禁用和危险状态均有明确表现。
- 触摸流程完整；涉及桌面时鼠标、键盘和焦点行为完整。
- 重要图标、选择、展开、图表和错误状态具有正确 Semantics。
- 行为测试通过；稳定且视觉敏感的共享组件补充必要 Golden。
- 文档、现状审计和组件目录与实现同步。

## 每次迁移的推荐步骤

1. 对照 `current-audit.md` 确定要解决的单一问题范围。
2. 阅读相关基础、组件、交互和响应式规范。
3. 先补行为或组件契约测试，再进行最小实现。
4. 运行本地化、Analyze 和相关 Widget 测试。
5. 完成 Definition of Done 的人工矩阵检查。
6. 更新迁移状态和已解决审计项。
7. 独立提交，避免与业务功能混在同一提交。

## 非目标

- 不一次性拆分整个 `app.dart`。
- 不引入新的 UI 框架替代 Material 3。
- 不为了 Design System 重写导航、Controller、FFI 或数据库。
- 不提前为未知桌面需求建立复杂适配层。
- 不建立庞大且无人使用的 token、组件或 Golden 集合。
